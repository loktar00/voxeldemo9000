# Voxel Space Terrain Renderer

Browser-based 3D voxel terrain renderer using Canvas 2D raycasting. No build system, no dependencies — vanilla HTML + JavaScript ES modules.

**[Live Demo](https://loktar00.github.io/voxeldemo9000/)**

## How to Run

Open `index.html` directly in a browser, or use any static file server:

```bash
npx serve .
# or
python -m http.server
```

**URL parameters:**
- `?terrain=temple` — Mayan temple only
- `?terrain=procedural` — Diamond-square terrain (default)
- `?seed=42` — Reproducible terrain generation

## How It Works

### Voxel Space Rendering

Column-based raycaster inspired by Novalogic's Comanche engine (1992). For each screen column, a ray is cast from the camera into the world at increasing depth steps. At each step the heightmap is sampled and a vertical strip is drawn from the terrain surface upward. A per-column `hiddenY` buffer tracks the highest pixel already drawn — any strip that falls behind it is culled. This front-to-back approach naturally handles occlusion without sorting.

### Terrain Generation

Diamond-square (midpoint displacement) on a 2048×2048 heightfield with toroidal wrapping so the terrain tiles seamlessly. Biome coloring uses height-based gradient stops — deep water, sand, grass, rock, snow — with smooth interpolation between stops. Grass blades are per-pixel height offsets generated by a deterministic integer hash, giving fine detail without additional geometry.

### Shadow Baking

At terrain generation time, each heightmap pixel ray-marches toward a virtual sun position. If any intervening pixel's height exceeds the ray's interpolated height, the pixel is marked as shadowed and its color is darkened in the colormap. Two light sources with different angles produce softer shadow edges. No per-frame lighting cost.

### Billboard Sprites & Depth Sorting

Entities (birds, creatures, stars) are projected into screen space using the same frustum math as the terrain renderer. A per-pixel depth buffer (`Float32Array`) is written during terrain rendering, storing the depth of every drawn pixel. Sprites check `spriteDepth < depthBuf[pixel]` before drawing each pixel — this gives correct per-pixel occlusion without needing to sort sprites by distance.

## Architecture

| File | Purpose |
|------|---------|
| `index.html` | Canvas, loading screen, settings overlay, FPS counter |
| `engine.js` | Init, game loop, resolution scaling, settings wiring |
| `renderer.js` | Voxel space raycaster, day/night cycle, fog, stars, billboard sprites |
| `terrain.js` | Diamond-square heightmap, biome colors, grass map, shadow baking |
| `camera.js` | Camera state and movement (fly + gravity modes) |
| `input.js` | Keyboard/mouse/pointer lock handling |
| `entities.js` | Birds (air) and deer (ground) — spawning, movement, respawning |
| `oldreference.js` | Preserved original prototype (not imported) |

## Credits & History

Original voxel space work dates back to 2013 or so. `oldreference` is the preserved prototype from that era.

The rendering technique was popularized by Novalogic's **Comanche: Maximum Overkill** (1992) and is commonly known as the "Comanche algorithm" or "voxel space" rendering.
